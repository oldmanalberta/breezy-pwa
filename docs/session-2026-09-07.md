## Features added to the web app

- **Daily panel** — Conditions, Precipitation and Wind now carry the previous 7 days to the left of today (Open-Meteo `past_days`). Slide the strip back to see them; a dashed rule marks where record ends and forecast begins. These are model-analysis values, not official station records.
- **Historical card** — the monthly strip scrolls, with mean daily high/low curves and precipitation totals labelled in mm. Under each month: the chosen year's high/low, then this year's beneath it.
- **Radar smooth motion** — three real bugs fixed: the flow renderer always fetched rain+snow regardless of layer (smoke came up blank); the 2-minute newer-scan poll used radar's time axis for every layer (smoke broke after a couple of minutes); the "did the GPU draw?" probe checked a near-empty frame and switched WebGL off on quiet days.
- **Zoom/pan in smooth motion** — the settle step after a gesture set `opacity: 0` on the WebGL canvas and never restored it. Frame canvases are also released after GPU upload (iOS silently blanks canvases once its memory budget is spent).
- **Smoke under smooth motion** — softening is now baked into each frame before upload instead of a CSS filter on the WebGL canvas, which WebKit could composite as an empty layer.
- **Smooth-motion toggle** on the radar screen (wave button under wind) to flip between raw scans and interpolated motion on the spot. Settings stays in step.
- **Radar diagnostics** (Settings) — toasts each loading stage for bug reports.
- Every renderer fallback now toasts its reason.

## Native shell

- Capacitor 8 with Swift Package Manager (no CocoaPods). `www/` is assembled by `tools/build-www.sh`; the synced copy under `ios/App/App/public/` is committed so Xcode builds without Node.
- 1024px icon and splash rendered from `tools/make_icons.py`. Portrait only, light status bar, location usage text.
- `tools/serve.command` — double-click to start the dev server and open `localhost:8712`.
- `tools/push.command` — double-click to commit anything pending and push to GitHub with the Mac's stored token. (Terminal can't be typed into from this side, and git lock files it leaves behind are cleared by this launcher.)

## Widgets (WidgetKit)

- `js/native.js` publishes a compact forecast snapshot on every paint; in the native shell it reaches the `WidgetBridge` Capacitor plugin (in `AppDelegate.swift`), which stores it in the App Group `group.ca.oldmanalberta.breezy` and asks WidgetKit to reload. No-op in a browser.
- `ios/widget-src/` holds the extension sources, copied into `ios/App/BreezyWidget/` over Xcode's template: **Forecast** (small/medium/large — current conditions, 5-day columns, or 7-day rows with hourly strip), **Hourly** (medium/large, with chance of precipitation), **Conditions** for the Lock Screen (circular/rectangular/inline). Weather glyphs are SF Symbols mapped from the app's condition keys; the background follows the app's sky gradient.
- The widget only updates when the app publishes, i.e. when Breezy is opened. Background refresh is a possible follow-up.

## Gotchas learned

- Xcode couldn't pair with the phone while the phone's VPN was on ("tunnel connection failed"). VPN off, replug, and Developer Mode then appears under Settings → Privacy & Security.
- "Scheme App is not testable" just means Cmd-U was pressed; Run is Cmd-R.
- GitHub needs a personal access token, not the account password, for `git push`.
- The "JS Eval error" line in Xcode's console at launch is the service-worker registration, which the native shell doesn't support and the app already catches.
